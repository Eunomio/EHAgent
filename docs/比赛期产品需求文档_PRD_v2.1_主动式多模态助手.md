# 比赛期产品需求文档（PRD）

> 文档版本：v2.1
> 最近修订：2026年8月31日
> 对应原型：Android 0.15.0＋Windows本地Agent
> 产品形态：以桌面机器人为目标载体的主动式多模态大模型助手“小安”

## 1. 产品定义

小安是面向居家老人的主动式大模型助手。大模型是负责理解、判断、沟通和编排任务的“大脑”；摄像头、无感睡眠助手及后续居家设备是获取信息和执行任务的“四肢”。系统通过设备事实、老人主动报告、本人可见画像和固定安全规则共同判断，在值得关注时主动沟通，并给出可执行的下一步。

产品包含两个相互关联的核心能力：

1. 跌倒风险关怀：VLM检查固定居家区域中的明显通行障碍，说明位置和处理方法，并支持稍后提醒、处理后复查及本人确认后的家属协助。
2. 心理健康风险线索关怀：比较老人自己的睡眠、心率、呼吸和作息基线，在连续变化且数据质量合格时主动询问身体感受、生活事件和主观原因，从审核资源库提供轻量支持。

两个能力共享画像和事件上下文。例如，老人明确提到跌倒经历后持续担忧，并同时出现睡眠变化时，小安可以询问担忧是否影响日常活动，但不得诊断焦虑、预测跌倒或自行生成治疗方案。

## 2. 目标与边界

- 首页以小安对话为主，安全、睡眠、主动关怀、联系人和设备状态作为可拖动模块；
- 小安通过大模型语义选择已连接设备工具，授权后完成真实调用；
- 首次设备控制只请求一次授权，老人可在独立隐私页撤回；
- 建立“设备线索→主动询问→老人回应→一项支持→记录与复查”的闭环；
- 建立本人可见、可追溯、可修改和可删除的老人画像；
- 不依据单次图像、心率、呼吸、睡眠或聊天诊断疾病；
- 不从症状、语气或设备数据推断具体疾病；
- 不未经授权联系家人、改变隐私设置或分享完整对话；
- LLM不得修改VLM结果、传感器数值、固定风险规则或紧急流程。

## 3. 信息架构

底部导航在首页和功能页保留：

1. 首页：小安对话为主，其他生活卡片可长按拖动排序；
2. 安全：摄像头状态、环境检查、风险位置、处理和复查；
3. 睡眠：睡眠及心率、呼吸数据，个人趋势与同步状态；
4. 隐私：摄像头、睡眠提醒、主动关怀、心理关怀、静默时段、设备控制授权；
5. 画像：基础引导、已保存事实、来源、修改与删除。

首页“完整对话”进入可滚动聊天页，展示完整回复、来源和点选动作，不用截断卡片承担完整阅读。

## 4. 小安与设备工具

每轮对话由大模型结合用户语义和设备状态输出结构化工具计划。当前工具包括摄像头状态、摄像头抓图＋VLM检查、读取／同步睡眠数据，以及安全检查、睡眠提醒和主动关怀的开启与暂停。

设备控制授权状态为`unset / allowed / denied`：首次请求显示“允许小安控制已连接设备／暂不允许”；允许后立即执行当前请求并在以后复用授权；拒绝后不执行，并提示可在隐私页修改。联系家人、共享敏感信息和修改隐私设置仍需独立确认，不被通用设备授权覆盖。

## 5. 老人画像

### 5.1 原则

- 画像是可解释事实，不是人格标签或医学诊断；
- 显性问题由老人点选确认；琐碎的低敏感偏好可在日常对话中推测记录；
- 跌倒经历、担忧、疾病、用药、联系人等敏感信息不得无感推断；
- `confirmed`和低敏感`inferred`事实都对老人本人可见，并显示来源；
- 老人可以修改、删除或停止使用相关信息；
- LLM每轮只读取当前任务所需的最小画像摘要。

### 5.2 基础引导题项

|序号|单一维度|互斥选项|保存字段|
|---|---|---|---|
|1|通常居住安排|一个人住；只和老伴住；与子女或其他家人住；其他居住安排|`living_arrangement`|
|2|长期健康管理状态|没有；有但不影响平时生活；有且影响日常生活；不确定|`health_management_status`|
|3|一次提醒的信息量|先说重点；说明原因和建议；详细说明原因、建议和下一步|`reminder_detail_preference`|
|4|提醒呈现方式|主要听语音；语音和屏幕同时；主要看屏幕文字|`interaction_mode_preference`|
|5|家人联系权限|仅明确紧急情况可直接联系、其他情况先问；每次都先问；小安不主动联系家人|`sharing_preference`|

“暂时不填”是回答状态，不与业务选项混在同一分类层级。选择后同样保存“该项暂不填写”，让老人知道操作已经生效。

### 5.3 健康情况两层记录

基础引导只记录是否存在经医生确认、需要长期管理的疾病及其日常影响，不要求一次选择所有疾病。老人可在对话中明确说出具体病名；系统将其保存为`candidate`并显示“记住／不用记”，点击“记住”后才成为`confirmed health_condition`。疾病名称和用药不得成为`inferred`事实。

### 5.4 保存、续填与修改

```text
首次进入→显示第一个未填写字段
每次选择或暂不填写→立即保存→进入下一个未填写字段
中途退出后再次进入→从第一个未填写字段继续
全部完成后再次进入→先展示已保存汇总
点击“修改某项”→只重问该字段→替换旧记录→返回已保存汇总
```

画像页按钮根据状态显示“开始填写／继续填写／查看或修改”。已保存区逐条展示内容和来源；删除后该字段恢复为未填写。

## 6. 跌倒风险关怀

C6c获取固定区域画面后，VLM输出可见障碍、位置和通行影响，固定规则决定风险等级。中高风险形成主动事件：

```text
说明“哪里、有什么、为什么影响通行”
→ 给出一个具体处理动作
→ 询问“您现在方便处理吗？”
→ 我现在处理／稍后提醒／我现在不方便
→ 仅当老人表示无法处理或主动求助时，提供“确认联系家人”
→ 整理后重新抓图复查
```

普通纸箱场景不得直接写成老人害怕或立即请求家人。合理演示是小安识别通道障碍后询问是否方便移开；只有老人明确表示身体不便、物品太重或希望协助时，才进入家属帮助。

## 7. 心理健康风险线索关怀

- 至少形成个人睡眠基线，并在连续变化时才触发普通主动询问；
- 先检查设备在线、数据缺失、时区和测量质量；
- 先陈述事实，再问当天感受和可能原因；
- 单一生理变化只触发身体感受确认，不形成心理风险结论；
- 支持内容来自审核资源库，包括白噪音、呼吸放松、睡前建议和轻量活动；
- CBT／CBT-I仅使用审核后的结构化内容，LLM负责匹配和解释；
- 明确自伤、自杀、失去意识、胸痛、呼吸困难或严重跌倒进入固定紧急流程。

## 8. 主动打扰与隐私

- 同一来源事件去重，普通事件遵守静默时段和每日上限；
- “稍后再说”不会被解释为拒绝治疗或风险升级；
- 摄像画面不默认发送给通用对话LLM，LLM接收结构化风险结果；
- 家属默认只看本人允许的风险摘要、帮助请求和下一步；
- 所有主动事件显示触发原因，并允许暂停对应关怀；
- 健康情况、心理对话和家属分享采用独立可撤回边界。

## 9. 验收标准

### 9.1 画像

- 五道引导题分别只测量一个维度，选项之间不存在含义重叠；
- 每次选择和暂不填写都能在画像页立即看到；
- 中途退出后从未完成项继续，不重问已经保存的题；
- 完成后重新进入先看到保存汇总和五个单项修改按钮；
- 修改一项只替换该字段，其他记录保持不变；
- 明确说“医生说我有高血压”只产生待确认事实，点击“记住”前不进入正式画像；
- 系统不能从睡眠、心率、呼吸或情绪表达生成疾病事实。

### 9.2 系统

- “帮我看看家里现在怎么样”可经大模型选择摄像头＋VLM工具；
- 环境风险默认询问是否方便处理，不默认建议联系家人；
- 睡眠变化事件能展示触发依据、接收原因并推荐一项固定支持；
- 同一事件不重复主动打扰；
- 设备控制授权只询问一次，隐私页可撤回。

## 10. 五分钟演示

1. 完成五项基础引导，展示每次选择立即出现在画像页；
2. 退出后再次进入，展示保存汇总；只修改“提醒方式”，证明不会从头重问；
3. 在日常对话中说“医生说我有高血压”，展示“记住／不用记”，确认后回画像页查看来源；
4. 对小安说“帮我看看家里现在怎么样”，展示一次设备授权、语义工具调用和VLM结果；
5. 环境中放置影响通行的物品，小安询问是否方便处理；选择处理并复查；
6. 展示连续睡眠变化触发的主动关怀，老人说明原因后选择一项固定支持；
7. 打开隐私页，展示设备控制、主动关怀和分享权限可撤回。

演示证明多模态线索整合、语义设备调用、本人可控画像和主动关怀闭环的可行性，不证明疾病诊断、真实跌倒预测或长期治疗效果。
