# 比赛期产品需求文档（PRD）

> 文档版本：v1.9
> 最近修订：2026年8月24日
> 目标提交日期：2026年9月5日
> 产品定位：比赛可运行原型
> 产品形态：安卓APK住户端 + Windows本地Agent + 本地调试与评测工具

本次修订升级通道视觉监测与风险处置闭环。系统自动识别通道参考画面，优先通过萤石移动告警快速触发检查，并用本地画面变化检测兜底；风险框与实际通道边界的重叠比例用于纠正“物品在边缘”等矛盾结论。住户端使用绿色、黄色和红色区分安全、潜在风险和必须整改，实时画面标出最近检查发现的风险位置。红色风险支持系统通知、针对性整改建议、30分钟后提醒、整理后复查以及`ecnu-tts`中文语音播报。

## 1. 本次要交付什么

本次交付重点是让主要功能可以安装、操作、测试和演示。住户使用安卓APK，Windows电脑运行本地Agent；研发和演示人员通过OpenAPI页面、本地脚本及离线标注页完成配置与验证。

住户端首页优先展示两个核心生活功能和一个共用入口：

1. 通道安全；
2. 睡眠与身体趋势；
3. 帮助与设置。

通道安全完成主要Agent闭环，使用真实C6c和萤石开放平台完成取图、风险判断、整改提醒与复查。睡眠模块接入无感睡眠伴侣的睡眠、呼吸频率和心率数据，完成个人趋势总结、本人确认和请求家人联系。帮助与设置提供家属响应、摄像头暂停和数据控制。访客确认保留为扩展演示，不占用主线算法开发资源。

当前使用安卓手机开发和真机测试，同时用Android Emulator检查手机和平板尺寸。以后可根据需要购买安卓平板，并在拿到萤石RK3后继续适配。

## 2. 产品目标

- 老人打开APK后能直接看懂通道安全、睡眠趋势和帮助入口；
- C6c在一个固定非隐私通道完成真实取图和风险复查；
- 通道出现明显障碍物后，页面给出位置、原因和处理动作；
- 首次使用时由后台自动识别通道，用户无需手动拍摄或设置安全基准图；
- 实时画面使用黄框和红框标出最近一次检查发现的潜在风险与整改位置；
- 黄色风险只提示留意，红色风险生成整改任务并发送一次系统通知；
- 同一风险经过连续确认后只主动提醒一次，卡片保留到处理完成；
- 整改提醒支持中文语音，语音失败时文字、任务和复查仍可正常使用；
- 每晚生成包含睡眠时长、呼吸频率和心率的总结；
- 数据满足条件时展示最近7天趋势，只提示“与平时不同”；
- VLM提供可见原因，固定规则生成简短、具体、可执行的通道整改文案；
- LLM不可用时自动使用固定模板，睡眠总结、反馈和生活助手仍保留基础能力；
- 老人能从任意主页面打开“小安”，用文字或语音提出问题；
- 小安能引用当前安全提醒、最近睡眠和家庭设置，也能回答一般生活问题；
- 天气、新闻、政策、交通和近期诈骗信息等时效内容按需查询，并给出可打开的来源；
- 联系家人等实际动作先展示确认按钮，老人确认后执行；
- 老人可以请求家人协助处理环境问题或联系本人；
- 老人可以暂停摄像头或某类提醒；
- 新来访者确认作为扩展演示，不输出诈骗或身份结论；
- 工程人员能在Windows电脑测试设备连接、运行离线VLM评测并查看接口结果；
- APK能在安卓手机安装运行，并能连接同一局域网内的Windows Agent；
- 比赛演示可以通过初始化数据重复执行。

## 3. 产品形态与角色边界

### 3.1 安卓住户端

住户端只展示老人日常需要的信息和操作：

- 通道检查状态与风险提示；
- 最近一次风险位置、整改建议和语音播放；
- 当天睡眠、呼吸频率和心率总结；
- 最近7天的个人趋势；
- 家属联系状态、摄像头暂停和提醒设置；
- 扩展来访确认；
- 清晰的大按钮和中文语音；
- 全局生活助手、语音提问、回答朗读和信息来源。

APK中不显示试验图片、模型参数、规则阈值、日志、接口地址、内部任务编号和测试状态。Agent地址由工程人员在安装配置中设置。

### 3.2 Windows本地调试与评测工具

当前版本没有独立的Windows Web工程台。研发和演示人员使用FastAPI OpenAPI页面、本地脚本和离线标注页面完成：

- 接入和测试摄像头；
- 接入和测试无感睡眠伴侣数据；
- 采集少量C6c试验图片；
- 制作VLM离线评测标签并运行回归测试；
- 查看自动通道参考、识别结果、规则结果和任务状态；
- 配置VLM、LLM、TTS和固定规则参数；
- 初始化或重置比赛演示数据；
- 区分真实设备数据和明确标记的演示数据；
- 查看运行日志和评测结果。

这些工具只供安装、开发和比赛演示使用，不出现在住户APK中。当前Agent需要监听局域网地址供APK连接，因此只在同一家庭可信网络中运行；以后部署到公网前必须补充登录、HTTPS和接口授权。

### 3.3 Windows本地Agent与LLM模块

Windows本地Agent负责连接设备、保存状态、执行固定规则、调用视觉大模型、管理任务闭环、生成语音并向安卓端提供数据。视觉大模型输出通行影响、绊倒风险、可见原因、归一化风险框和近处通道开口；固定规则校正风险等级并生成整改动作。当前版本不训练或加载RTMDet等传统目标检测模型。LLM模块处理睡眠总结、老人反馈和生活助手对话，不参与当前自动通道检查的最终风险判断。

LLM处理以下内容：

- 根据真实睡眠时长、呼吸频率、心率、离床次数和近7晚统计，生成生活化睡眠总结；
- 将老人提交的使用感受、身体感受或帮助说明整理成简短摘要，供家属或工程人员查看；
- 根据后端整理的家庭信息和最近对话回答生活问题，并对联系家人等动作要求二次确认；
- 为早期`/ingest/safety-results`兼容接口整理旧版安全结果文案，该接口不属于当前自动监测主流程。

语音提醒调用ECNU兼容的文本转语音接口，模型名为`ecnu-tts`。语音内容由风险标题、可见原因和整改建议组成；API Key只保存在Windows端。语音生成失败时，APK继续展示同一份文字内容，并允许用户稍后再次播放。

LLM不得：

- 修改VLM输出、通道判断、连续确认次数或任务状态；
- 根据睡眠、呼吸频率和心率诊断疾病；
- 生成未出现在输入数据中的人物、物品、生命体征或处理结果；
- 自动拨号、联系家属、删除记录或控制设备。

LLM API Key只保存在Windows电脑的`.env`，不写入APK、数据库、日志或GitHub。每次调用保存用途、实体ID、使用模型、结果来源和时间，不保存API Key。LLM超时、限流、返回格式错误或未配置时，Agent立即使用对应固定模板。

## 4. 安卓住户端信息架构

### 4.1 首页

首页使用三个大卡片，不以设备作为一级入口。

|卡片|主要内容|主要动作|
|---|---|---|
|通道安全|C6c在线/暂停状态、检查区域、待处理风险、最近检查时间|检查一下、查看详情|
|睡眠与身体趋势|昨晚睡眠时长、呼吸频率、心率、是否与个人平时接近|查看详情、回应提醒|
|帮助与设置|家属联系状态、摄像头状态、提醒开关|联系家人、暂停摄像头、调整提醒|

首页不创建教学任务、演示任务或测试任务。没有正式结果时显示“暂时没有新的记录”或对应模块的自然提示。

### 4.2 适老化要求

- 默认正文字号不小于20sp，重要数字和标题使用更大字号；
- 主要按钮触控高度不小于48dp；
- 一屏只突出一个主要动作；
- 文字和背景保持高对比度；
- 状态同时使用文字与颜色表达；
- 重要提醒支持中文语音，语音内容与页面文字一致；
- 手机宽度使用单列，平板宽度使用双列、三列或主从布局；
- 页面不出现横向滚动，关键按钮不依赖精细点击；
- 文案自然、简短、具体，直接说明发生了什么和可以怎么做。

### 4.3 全局生活助手“小安”

#### 用户场景

- 老人在首页、安全、睡眠或“我的”页面看到右下角“问小安”，点击后打开完整对话页；
- 首次打开时看到“昨晚睡得怎么样”“今天适合出门吗”“这个电话像诈骗吗”“帮我联系家人”四个常用问题；
- 老人可以输入文字，也可以点击麦克风说出问题；发送后当前问题立即显示，回答完成后显示在下方；
- 老人点击回答下方的扬声器即可朗读全文；
- 回答使用了最近睡眠、安全提醒等家庭信息时，页面显示“参考了：最近一次睡眠”等简短说明；
- 回答包含天气、新闻、政策、交通或近期诈骗信息时，页面显示来源卡片，点击后用浏览器打开原页面；
- 老人说“帮我联系家人”后，页面显示“确认联系家人”；只有点击确认后，家庭帮助列表才新增请求；
- 关闭再打开应用时，最近一次对话仍可继续。

#### 页面内容与交互

- 顶部显示“小安”和返回按钮；
- 中部按时间展示本人问题和小安回答，本人消息与回答使用不同颜色；
- 底部固定展示语音按钮、文字输入框和发送按钮；
- 回答等待期间显示“小安正在想…”；
- 家庭服务暂时无法连接时，保留已有对话并提示稍后重试；
- 页面不展示模型名称、接口地址、联网工具、调用状态或内部记录编号。

#### 使用信息规则

每轮对话只整理回答当前问题所需的家庭摘要，包括最近一次睡眠、当前安全提醒、摄像头与睡眠提醒开关、设备连接状态和家人称呼。历史对话最多取最近10轮。原始摄像头画面、设备密钥、联系电话和历史完整传感器序列不发送给生活问答。

天气、新闻、政策、交通和近期诈骗信息可能变化，小安按问题需要查询公开信息并返回来源。普通闲聊或已经能由家庭摘要回答的问题无需查询。涉及身体不适时提供清晰的下一步建议；胸痛、呼吸困难、失去意识或正在跌倒等紧急描述优先提示呼叫急救和联系身边的人。

#### 验收结果

- 四个主页面都能在一次点击内打开“小安”；
- 文字提问、语音转文字、发送、回答朗读均可在安卓真机完成；
- 输入“昨晚睡得怎么样”后，回答中的睡眠时长、心率和呼吸频率与首页最近记录一致；
- 输入一个需要近期信息的问题后，回答至少显示一个可正常打开的来源；
- 输入“帮我联系家人”后，点击确认前帮助列表不新增记录，点击确认后只新增一条；
- 重启应用后能恢复最近一次对话；
- 后端未配置生活问答服务时，安全和睡眠问题仍能得到基于现有数据的简短回答；
- 回答失败时页面不丢失已有消息，可以再次发送。

## 5. 通道安全模块

### 5.1 首页卡片

卡片展示：

- C6c在线、离线或已暂停；
- 当前检查区域，例如“卧室外走道”；
- 当前通道状态和对应颜色；
- 当前需要处理的风险；
- 一条具体整改建议；
- 最近检查时间；
- “检查一下”和“暂停摄像头”按钮。

首页不默认持续播放直播。用户主动进入详情页时才允许打开画面。

住户端使用三种容易理解的状态：

|页面状态|内部风险|颜色|页面动作|
|---|---|---|---|
|通道安全|`clear`|绿色|不创建任务，不主动提醒|
|潜在风险|`low`|黄色|提示留意，不要求整改|
|需要整改|`medium`、`high`|红色|创建整改任务，首次出现或风险升级时提醒|

颜色必须与“通道安全”“潜在风险”“需要整改”等文字同时出现。纸箱等日常物品位于通道边缘、无需绕行或跨越、没有进入常用落脚区域时保持绿色，不因画面中存在物品而要求整改。

### 5.2 二级页面

页面包含：

- 摄像头状态和当前检查区域；
- 用户主动打开的实时画面或最近一次风险缩略图；实时画面由萤石Android SDK的EZPlayer按设备和通道取流，可播放C6c的H.264/H.265码流；
- 最近一次检查返回的风险框；
- 当前风险等级、可见原因和具体整改建议；
- 最近检查时间和语音播放按钮；
- 通道自动识别状态；
- 最近已完成记录；
- 数据保存和自动删除时间。

实时画面的风险框遵循以下规则：

- 黄色框表示需要留意但当前仍可正常通行的位置；
- 红色框表示需要整改的物品；
- 画面同时显示“最近检查位置”，说明框来自最近一次截图分析；
- 风险框使用0至1000的归一化坐标，适配普通画面与横屏全屏画面；
- 模型没有可靠坐标、坐标越界、范围过小或通道已经安全时不显示风险框；
- 摄像头开始转动后立即隐藏旧风险框，等待新视角重新识别和检查；
- 风险框只帮助用户找到物品，文字风险等级和整改建议仍是主要信息。

摄像头和页面支持以下操作：

- 检查一下；
- 启动或停止画面；
- 横向全屏查看，控制手柄位于右下角；
- 上、下、左、右移动摄像头；
- 暂停或恢复自动检查；
- 重新识别通道；
- 播放当前红色风险的语音提醒；
- 删除已保存的风险图片。

用户无需手动设置安全基准图。后台没有通道参考或摄像头角度明显变化时，自动抓取当前画面并检查是否适合作为通道参考。画面可正常通行时自动保存；暂时不适合时每60秒重新尝试。页面保留“重新识别”入口，供用户主动更新。

### 5.3 环境风险Agent闭环

```text
C6c每2秒通过萤石设备告警接口确认移动事件
→ 收到移动告警后等待画面稳定1秒
→ 萤石告警接口超时或调用失败时，改用本地图片差异检测
→ 8秒未收到移动告警时执行一次本地兜底检查
→ 本地画面变化以1秒间隔连续确认2次
→ 视觉大模型比较当前画面与后台通道参考
→ 输出通行影响、绊倒风险、物品类型和风险框
→ 固定规则生成绿色、黄色或红色状态
→ 红色风险创建整改任务，生成具体建议、系统通知和中文语音
→ 住户选择“我已整理好”“30分钟后提醒”或“联系家人”
→ “我已整理好”立即重新抓图复查
→ 更新为通道畅通、仍需整理或暂时看不清
```

通行空间和跌倒风险分别判断。即使仍有空间通过，只要物品伸入常用落脚区域、需要绕脚或跨越，仍可判定为红色风险。视觉分析同时返回基准图近处可通行开口的左右边界。固定规则计算风险框与该开口的重叠比例，不使用整张画面的几何中心代替通道中心。近处物品覆盖通道宽度25%以上时至少提升为需要整改，覆盖50%以上时提升为严重风险；几何结论与“物品位于边缘”的文字冲突时，以风险框和通道边界的重叠结果为准，并同步修正页面原因。

整改建议根据物品类型生成：纸箱和袋子移到通道外，鞋子收入鞋柜或靠墙摆放，凳子移出行走路线，电线沿墙固定。无法识别具体物品时使用“将影响行走的物品移到通道外”。

同一区域只保留一张活动卡片。相同红色风险持续存在时只更新时间，不重复发送通知或自动播放语音；黄色升级为红色、一般整改升级为严重风险时再次提醒。风险处理完成后关闭当前任务。

自动识别范围只包含一个固定通道内的明显物品侵入。比赛版不自动判断地面湿滑、照度、物品重量、身体不适或未来是否会跌倒。

#### 结构化结果

每次正式检查至少保存以下内容：

|字段|用户可观察结果|
|---|---|
|`check_id`|同一次结果、通知和语音使用同一标识，避免重复处理|
|`risk_level`|映射为绿色、黄色或红色状态|
|`headline`|说明当前通道状态|
|`reason`|说明画面中可以看到的依据|
|`action_text`|给出针对物品的下一步动作|
|`hazard_regions`|包含物品标签、风险等级及0至1000归一化坐标|
|`walkway_near_x1`、`walkway_near_x2`|基准图中画面近处实际可通行开口的左右边界|
|`notification_required`|只有首次红色风险、风险升级或延后到期时为真|
|`speech_auto_play`|本次识别需要自动播报时为真；同一自动监测风险持续存在时为假|
|`speech_url`|红色风险可播放的语音地址；黄色和绿色为空|
|`checked_at`|页面显示的最近检查时间|

结构化结果与检查截图绑定。风险框无法可靠生成时，`hazard_regions`为空；风险等级、原因、建议和任务仍然保留。

### 5.4 防打扰与隐私规则

- 萤石移动告警触发后等待1秒再抓图，减少人物仍在移动时的误判；
- 萤石告警接口超时或调用失败时自动使用本地图片差异检测；8秒未收到告警时执行一次本地兜底检查；
- 本地画面变化需要连续确认2次后才调用视觉分析，短暂经过的人影或光线闪动不立即触发；
- 自动分析结束后至少10秒内不再次调用；
- 手动检查或复查识别到红色风险后立即自动播放语音，无需点击播放按钮；
- 自动监测首次识别到红色风险时发送一次系统通知并自动播放一次语音；
- 风险等级升级时允许再次通知和播放语音；
- “30分钟后提醒”隐藏当前卡片，30分钟后风险仍存在时重新显示并提醒；
- 用户可以手动再次播放当前语音；
- TTS超时、限流或返回无效音频时只显示文字建议，不影响任务和复查；同一次检查至少间隔60秒再尝试播放；
- Android 13及以上首次使用系统通知时申请通知权限；
- APK进程仍在运行时轮询最新风险并发送系统通知；进程被系统结束后保留活动任务，下次打开时继续提醒；
- 默认不保存连续视频；
- 无风险图片处理完成后删除，只保存结构化结果；
- 风险图片按设置的期限自动删除；
- 暂停后停止应用侧自动取图，并在首页持续显示“摄像头已暂停”。

应用被系统彻底结束后仍即时到达的远程推送需要独立配置Firebase Cloud Messaging。本阶段没有Firebase项目凭证时，不宣称具备这种后台远程推送能力。

### 5.5 通道安全模块验收

- 能通过萤石开放平台取得C6c设备状态和有效图片；
- C6c产生新的移动告警后，系统可以自动抓图并启动通道检查；
- 萤石告警接口超时或返回错误时，本地画面变化检测仍能触发通道检查；
- 重复返回同一告警编号时只触发一次检查，其他设备或通道的告警不会触发当前通道；
- 连续20次真实取图至少19次成功，失败时不生成风险结论；
- 首次启用无需用户拍摄基准图，后台能够自动识别并保存可通行参考；
- 摄像头角度明显变化后旧风险框消失，后台能够重新识别通道；
- 画面稳定变化后能够自动检查，无变化时不重复调用视觉分析；
- 绿色、黄色和红色状态同时使用颜色和文字表达；
- 通道边缘不影响通行的物品不生成整改任务；
- 物品横跨近处落脚区域时生成红色整改状态；
- 摄像头构图偏左或偏右时，使用实际通道开口判断，不能用整张画面中心误判物品在边缘；
- 模型文字称物品在边缘、但风险框覆盖近处通道50%以上时，最终显示严重风险及纠正后的可见原因；
- 可靠坐标能够在普通画面和横向全屏画面显示风险框；
- 无效坐标不会导致检查失败，也不会在错误位置显示框；
- 提醒包含位置、可见原因和针对物品的建议动作；
- “已处理”后可以重新抓图并更新结果；
- 复查仍有风险时文案明确显示“再次检查，通道仍需整理”；
- “30分钟后提醒”后卡片暂时隐藏，时间到且风险仍存在时重新出现；
- “需要家人帮忙”可以生成家属待办；
- 暂停后不再自动取图，恢复后可以继续检查；
- 相同风险不会重复创建任务、系统通知或自动播放语音；
- 风险升级时能够再次发送系统通知；
- `ecnu-tts`可以返回有效MP3并在安卓真机播放；
- TTS失败时页面文字、整改操作和复查仍可使用；
- 真实设备、回放和人工素材保持独立来源标记。

比赛测试集采用以下量化目标：

|指标|目标|
|---|---:|
|需要整改召回率|≥90%|
|高风险漏检率|≤5%|
|边缘安全物品误整改率|≤5%|
|可靠风险框定位有效率|≥90%|
|相同事件重复通知次数|0|
|萤石告警产生至开始安全分析P95|≤5秒|
|本地兜底发现稳定变化至开始安全分析P95|≤12秒|
|后台生成结果至APK刷新P95|≤4秒|
|画面稳定变化至结果生成P95|≤60秒|
|TTS成功返回有效音频比例|≥95%|
|复查结果与当前任务状态一致率|100%|

风险框定位有效率只统计人工确认“存在可见风险物品且适合画框”的图片。框与物品有明显重叠、标签正确且颜色与最终风险一致时记为有效。

## 6. 睡眠与身体趋势模块

萤石无感睡眠伴侣具备无感监测睡眠、呼吸频率和心率的设备能力，并可形成睡眠报告；官方产品资料还提到离床未归、心率异常和体动异常等提醒。比赛版只使用当前账号和开放接口能够真实取得的字段，不根据缺失字段生成模拟的正式结果。

### 6.1 首页卡片

展示昨晚最近一次有效睡眠：

- 开始时间和结束时间；
- 睡眠时长；
- 平均呼吸频率，单位“次/分”；
- 平均心率，单位“次/分”；
- 与个人最近7晚是否接近；
- 一句状态提示。

当设备或接口没有返回某项数据时，该项显示“暂未同步”，不使用0填充。首页只展示平均值和自然语言趋势，不展示复杂波形。

### 6.2 二级页面

页面包含：

- 昨晚睡眠开始、结束和总时长；
- 呼吸频率的平均值；接口提供时展示最低值、最高值和夜间趋势；
- 心率的平均值；接口提供时展示最低值、最高值和夜间趋势；
- 离床次数、夜间觉醒次数或睡眠周期，仅在真实字段可用时展示；
- 最近7晚的睡眠时长、平均呼吸频率和平均心率趋势；
- 当前提醒与本人回应；
- 数据来源时间和最近同步状态。

比赛版按以下顺序接入数据：

1. 无感睡眠伴侣经萤石开放平台或获批接口返回的真实数据；
2. 设备或萤石云视频APP授权导出的数据；
3. 明确标记的回放或预置演示数据。

Windows Agent为每条记录保存数据来源。正式统计只使用真实设备或符合研究授权的导入数据。

### 6.3 数据字段与质量要求

最小数据对象包含：

- 本地睡眠记录ID和平台报告编号；
- 无感睡眠助手独立设备序列号，住户端不显示；
- 报告日期和时区；
- 睡眠开始和结束时间；
- 总睡眠时长；
- 呼吸频率平均值及单位；
- 心率平均值及单位；
- 数据生成时间和收到时间；
- 数据来源；
- 数据完整性或设备提供的质量状态。
- 报告状态，包括初步、最终或修正；

接口提供时继续保存睡眠得分、清醒时长、浅睡时长、深睡时长和快速眼动时长。每个时序采样点可以包含采样时间、呼吸频率、心率、是否在床和体动数值；每个睡眠阶段区间包含开始时间、结束时间和阶段类型。

接口提供采样序列时，再保存呼吸频率和心率的时间戳序列、最低值、最高值。接口只提供夜间汇总时，页面只展示汇总值，不补造曲线。

呼吸频率、心率存在缺失、时间错位、设备离线或质量不足时，该晚不参与个人基线计算。原始设备数值和Agent生成的趋势结论分开保存。

### 6.4 个人基线与提醒规则

- 以一晚有效睡眠为一个总结单位；
- 同一次睡眠只主动提醒一次；
- 数据更新时更新原有总结，不连续创建新提醒；
- 使用最近7至14晚同来源、状态为最终或修正且质量可用的记录建立个人基线；
- 当前一晚之外至少需要7晚有效历史，因此首次完整比较通常需要累计8晚记录；
- 睡眠时长、平均心率和平均呼吸频率分别与个人历史中位数比较；
- 变化至少达到45分钟、每分钟5次心率或每分钟2次呼吸频率，并在历史波动可计算时达到稳健偏离阈值，才标记为“与个人近期水平有明显差异”；
- 数据不足时显示还需要多少晚有效记录，不提前生成偏离结论；
- 呼吸频率和心率在比赛版优先展示趋势，不自行输出疾病或紧急结论；
- 若设备或平台提供原生异常事件，系统可以转为“设备提示这项数据需要关注”，同时保留事件来源；
- 本人回应包括“我没事”“希望家人联系我”“这几天情况特殊”“暂停这类提醒”；
- 选择“希望家人联系我”后生成家属待办；
- 没有数据时显示“昨晚的睡眠数据暂未同步”。

提示文案只说明数据与个人平时是否不同。页面不输出抑郁、认知障碍、失眠、心脏病、呼吸系统疾病等判断。老人表示身体不舒服时，页面提示联系家人或按既有方式寻求医疗帮助。

### 6.5 实时离床、呼吸和心率边界

- 设备具备实时检测能力，不等于当前开放接口一定提供实时采样；
- 只有实际接口能够返回事件级离床数据且端到端延迟通过测试，才开启实时离床提醒；
- 只有实际接口提供实时呼吸频率或心率采样，页面才显示“当前值”；
- 接口只提供睡眠报告时，统一展示为“昨晚数据”；
- 离床实时提醒启用前需验证事件时间、延迟、补发和误触发；
- 当前没有可控智能灯具，比赛版不承诺自动开灯；睡眠伴侣自身的夜灯功能只按设备实际可控制能力使用。
- 若开放接口提供夜灯开关或模式控制，可在设置页增加“跟随设备设置”；若接口未提供，继续使用睡眠伴侣原有的本机或萤石云视频APP设置。

当前代码已提供起夜关注的数据结构、固定规则和演示入口。只有事件来源可靠、与睡眠记录来源一致、个人基线可用且至少两项指标可比较时，才显示常规关注或额外留意；其他情况显示数据不足。建议固定为“先在床边坐稳片刻、打开照明、扶稳后再行走”，不会输出跌倒概率。真实萤石事件级离床接口尚未取得非空验证结果时，正式页面保持等待状态，演示数据必须带有`demo_generated`来源。

### 6.6 睡眠模块验收

- 能接收至少一晚真实睡眠伴侣数据或授权导出数据；
- 能展示睡眠时间段、总时长、平均呼吸频率和平均心率；
- 缺少呼吸频率或心率时显示“暂未同步”，不显示0或模拟数值；
- 有7晚有效数据时能展示睡眠时长、呼吸频率和心率趋势；
- 累计当前晚和至少7晚有效历史后，个人基线可以返回各指标中位数、差值和比较状态；
- 起夜事件来源未验证或与睡眠记录来源不一致时，关注结果显示数据不足；
- 起夜演示数据不会与真实睡眠记录混合计算；
- 规则触发后能完成本人回应；
- “希望家人联系我”能生成家属待办；
- 同一睡眠记录更新后不重复主动提醒；
- 相同设备序列号和平台报告编号重复推送时更新同一记录；
- 未携带接收凭证、缺少设备序列号或序列号不匹配时拒绝写入；
- 真实设备、授权导入和预置数据保持来源隔离；
- 实时字段只在接口真实提供并通过延迟测试时展示；
- 预置演示数据可初始化和重置。

### 7.1 首页卡片

展示：

- 待处理家属事项数量；
- 摄像头正在检查或已暂停；

比赛版使用同一局域网内的家属Web页面，不接入短信、电话或微信。家属页显示请求类型、发生时间、老人希望得到的帮助和当前状态，提供“已看到”“已联系”“已完成”三个操作。

环境整改请求不设置紧急倒计时。睡眠趋势请求也不自动标记为紧急。系统记录老人请求到家属查看、联系和完成的时间。

### 7.3 隐私与数据设置

- 查看C6c当前检查区域和隐私遮罩；
- 一键暂停或恢复自动取图；
- 设置风险图片自动删除期限；
- 删除已保存的风险图片；
- 暂停睡眠趋势提醒；
- 查看哪些数据会发送给家属；
- 家属默认只看到风险摘要、老人主动请求和需要的下一步，不查看连续视频或完整生命体征曲线。

### 7.4 帮助与设置验收

- 三种入口均能生成一条家属待办；
- 家属可以完成查看、联系和完成回执；
- 相同请求不会重复生成；
- 暂停摄像头后自动取图停止且状态持续可见；
- 暂停睡眠提醒后仍保存用户已授权的数据，但不主动提醒；
- 删除风险图片后页面和存储记录一致；
- 家属页不展示连续直播和完整生命体征曲线。

## 8. 来访确认扩展模块

该模块用于展示可扩展业务流程，只识别“发生了一次来访并等待本人确认”。当前没有门铃或门外摄像设备，不在开门前判断门外人员，不做人脸身份识别，不输出诈骗结论。

### 8.1 扩展入口

## 10. 安卓与Windows连接

- Windows电脑运行FastAPI本地Agent；
- Android Emulator访问`http://10.0.2.2:8000`；

## 13. 文案规则

- 老人端只写老人需要看的生活信息和操作；
- 工程术语只放在研发文档、OpenAPI页面和日志中；
- 不在老人端写测试说明、研发背景、答辩话术和防御性说明；
- 不使用“演示任务”等与老人生活无关的名称；
- 少用抽象、公文化的词，优先描述具体动作和结果；
- 无数据时只说明“暂时没有新的记录”，不补充冗长解释；
- 风险提示使用“位置 + 发现内容 + 建议动作”的结构。
- 睡眠和生命体征只描述数值、时间范围及“与个人平时相比”的变化；
- 数据缺失时写“暂未同步”，不写0或“正常”；
- 设备原生异常事件写“设备提示这项数据需要关注”，不写疾病名称；
- 家属通知直接说明老人希望得到什么帮助。

示例：

- “走廊中间有一个纸箱，建议移到墙边。”
- “昨晚睡了7小时20分钟，平均呼吸频率是每分钟16次，平均心率是每分钟62次。”
- “昨晚的睡眠时长与个人近期水平有明显差异，建议结合起床后的实际状态观察。”
- “我需要家人帮忙移开走道里的纸箱。”
- “门口有一位来访者，请确认是否认识。”

## 15. 建议演示流程

1. 在Windows电脑启动Agent，并用OpenAPI页面确认服务可用；
2. 手机与电脑连接同一网络，打开安卓APK；
3. 展示通道安全、睡眠与身体趋势、帮助与设置三个首页卡片；
4. OpenAPI设备状态接口显示C6c来自萤石开放平台且设备在线；
5. 展示系统已自动识别通道，住户无需手动设置参考图；
6. 将纸箱放到通道边缘，确认页面保持绿色且不要求整改；
7. 将纸箱移入近处落脚路线，由萤石移动告警触发检查并生成红色风险；
8. 打开实时画面和横向全屏，确认红框覆盖纸箱位置，系统通知和中文语音各出现一次；
9. 点击“30分钟后提醒”或“需要家人帮忙”，展示对应任务变化；
10. 移开纸箱，点击“我已整理好”并复查为通道畅通；
11. 移动摄像头，确认旧风险框消失并自动重新识别通道；
12. 暂停摄像头，确认系统停止自动取图且首页状态清楚；
13. 打开睡眠页，展示昨晚睡眠时长、平均呼吸频率和平均心率；
14. 展示最近7晚趋势及一次“与平时不同”的本人确认；
15. 选择“希望家人联系我”，家属页完成联系回执；
16. 可选展示一条明确标记来源的来访确认扩展流程；
17. 导入明确标记的睡眠演示数据，确认不会与真实设备数据混合计算个人基线；
18. 重置演示数据，确认演示可再次执行；
19. 展示平板模拟器适配截图。

## 16. 无感睡眠伴侣能力与接口闸门

萤石官方资料确认无感睡眠伴侣能够通过毫米波无感监测呼吸频率和心率，提供睡眠报告，并具备离床未归、心率异常和体动异常等设备能力。桌面版公开参数中的呼吸率范围为6—40次/分、精度为1次/分。

产品能力是否启用，以比赛账号、实际设备型号和开放接口实测为准：

1. 若接口返回夜间汇总，展示昨晚平均呼吸频率、平均心率和多日趋势；
2. 若接口返回时间序列，增加夜间趋势、最低值和最高值；
3. 若接口返回设备原生异常事件，按原始事件展示“需要关注”并询问本人；
4. 若接口返回实时离床事件且延迟通过测试，才增加实时离床提醒；
5. 若开放接口暂未提供某字段，使用授权导出数据完成离线验证，正式页面显示“暂未同步”；
6. 预置数据只用于演示与自动化测试，不能计入真实设备效果。
