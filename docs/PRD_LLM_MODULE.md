# PRD：Windows本地Agent的LLM解释模块

> 版本：v1.0  
> 日期：2026-08-16  
> 所属产品：居安 Agent

## 1. 目标

LLM把视觉模型、睡眠设备和老人反馈的结构化信息整理成简短、自然、可执行的中文。安全结论、生命体征数值和任务状态继续由真实设备、视觉模型与固定规则确定。

## 2. 用户场景

### 2.1 通道整改建议

视觉模型已经确认“卧室外走道存在纸箱”后，LLM生成：标题、发现内容解释和一条具体整改建议。老人端继续使用现有安全卡片展示。

### 2.2 睡眠结果分析

一晚睡眠数据写入后，LLM根据睡眠时长、平均呼吸频率、平均心率、离床次数和最近记录生成一段生活化总结。文案只描述记录和变化，不给出疾病判断。

### 2.3 老人反馈整理

老人输入使用感受、身体感受或帮助说明后，系统保存原文，LLM生成简短摘要、反馈类别和是否建议人工跟进。摘要不能覆盖原文。

## 3. 输入与输出

| 场景 | 输入 | 结构化输出 |
|---|---|---|
| 安全解释 | 位置、物品、模型说明、确定性结果 | `title`、`explanation`、`suggestion` |
| 睡眠分析 | 当晚真实字段、最近最多7晚记录 | `summary`、`attention`、`question` |
| 反馈整理 | 反馈主题和老人原文 | `summary`、`category`、`needs_follow_up` |

所有字段设置长度上限并由Pydantic再次校验。模型返回缺字段、无效JSON或超长文案时使用固定模板。

## 4. 运行和配置

配置只保存在Windows后端`.env`：

```dotenv
EH_LLM_ENABLED=true
EH_LLM_PROVIDER=openai
EH_LLM_API_KEY=
EH_LLM_MODEL=gpt-5.4-nano
EH_LLM_API_BASE=https://api.openai.com/v1
EH_LLM_TIMEOUT_SECONDS=15
```

APK不接触API Key。`EH_LLM_ENABLED=false`或没有Key时使用固定模板。

## 5. 内容要求

- 使用老人日常能理解的中文，避免模型、置信度、ROI、接口等词语；
- 一次只给出一个优先动作；
- 不增加输入中没有出现的事实；
- 睡眠内容不使用诊断、正常、异常、患病等结论；
- 身体不适时只建议联系家人或专业人员；
- 保留原始设备数据和模型结果，LLM文案单独保存。

## 6. 降级模板

- 安全：`{位置}发现{物品}，可能影响通行。建议将{物品}移到走道外。`
- 睡眠：`昨晚共睡眠{时长}。平均呼吸频率{数值}次/分，平均心率{数值}次/分。`
- 反馈：截取原文前160字作为摘要；涉及求助、安全、跌倒、疼痛或不适时标记为建议人工跟进。

## 7. 验收

- 配置有效Key后，三个场景能取得通过结构校验的结果；
- LLM不能改变视觉模型的`clear/obstacle/insufficient`结论；
- LLM不能改变睡眠原始数值；
- API超时、限流、无Key和无效JSON时自动使用模板；
- 老人端安全卡片和睡眠页能展示生成结果；
- 老人反馈同时保存原文和摘要；
- 日志和住户接口不包含API Key。
