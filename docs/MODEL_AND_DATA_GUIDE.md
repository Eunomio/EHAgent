# 基础模型、数据与上传方法

## 第一版只训练通道障碍物检测

建议从轻量目标检测模型开始，例如 `RTMDet-tiny`，输出 ONNX 后部署到家中电脑。它能在普通电脑上运行，标注方式清楚，开发量可控。第一版无需训练跌倒识别、情绪判断或医疗判断模型。

建议类别：

| 类别 | 收集内容 |
|---|---|
| `box` | 快递箱、纸箱、收纳箱 |
| `bag` | 手提袋、塑料袋、背包 |
| `shoe` | 单只或成对鞋子 |
| `stool` | 小凳、折叠椅 |
| `cable` | 横跨走道的电线、插线板线 |
| `other_obstacle` | 水桶、玩具、临时杂物等 |

模型负责找出物品，后端再用“检测框是否与走道区域重叠”判断是否提醒。这样可以针对每户家庭配置走道区域，减少靠墙正常收纳造成的误报。

## 需要的数据

先采集约 2,000–3,000 张 C6c 实际视角图片：

- 每类障碍物至少 250–400 个清晰实例。
- 至少 35% 为完全畅通的负样本。
- 覆盖白天、夜视、开灯、背光、轻微遮挡和不同摆放距离。
- 同一连续视频只抽取少量间隔帧，避免训练集和验证集高度重复。
- 按家庭或拍摄日期划分训练集 70%、验证集 15%、测试集 15%，同一段连续画面只能出现在一个集合。
- 标注目标框，并为每台相机保存一块走道多边形区域。

不要采集卫生间、换衣区等私密区域。出现人脸、门牌、纸面联系方式时，先做模糊处理。取得参与者明确同意后再上传研究数据。

## 验收目标

在独立家庭测试集上关注实际提醒效果：

- 走道障碍召回率至少 90%。
- 畅通画面的误报率低于 5%。
- 夜视画面单独统计，不能被白天样本平均值掩盖。
- 连续十次检查只生成一条同类待办，避免反复提醒。

达到这些指标后再逐步扩充更多家庭和物品。比赛阶段可把“跌倒风险”聚焦为可干预的环境风险，实施成本更低。

## 图片和标注如何发给后端

图片作为请求正文发送，`annotation` 使用 URL 编码后的 JSON 查询参数，坐标为图片像素：

```powershell
$annotation = [uri]::EscapeDataString('{"width":1920,"height":1080,"objects":[{"label":"box","bbox":[620,510,980,920]}],"walkway":[[380,1080],[1480,1080],[1120,420],[760,420]]}')
curl.exe -X POST "http://127.0.0.1:8000/api/v1/ingest/vision-samples?source=c6c_collection&annotation=$annotation" `
  -H "Content-Type: image/jpeg" `
  --data-binary "@D:\data\corridor\001.jpg"
```

后端把原图保存在 `evidence/vision-samples`，把文件位置和标注写入 SQLite。批量数据可按同一格式循环上传，或在训练前直接整理为 COCO 数据集。

## 模型怎样把结果发给产品

推理程序每次读取 C6c 抓图，完成目标检测和走道重叠判断后调用：

```text
POST /api/v1/ingest/safety-results
```

畅通发送 `clear`；发现障碍物发送 `obstacle`；过暗、遮挡或抓图损坏发送 `insufficient`。老人端下次刷新会读取真实任务并显示对应操作。
