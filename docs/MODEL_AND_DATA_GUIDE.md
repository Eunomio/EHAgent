# 视觉监测、试验数据与评测

当前通道安全功能使用视觉大模型（VLM）比较 C6c 当前截图与后台自动保存的通道参考画面，再由固定规则结合风险框和真实通道边界确定最终风险等级。

VLM 使用“物理致害潜势—情境可规避性”原则分析障碍。情境可规避性同时包含可察觉性和可避让性：模型先判断物品与实际行走轨迹、落脚区、转弯区、门口及门槛的关系，再结合可能接近方向、遮挡、地面反差、首次可见距离、反应距离和剩余避让空间判断绊倒风险。杂物数量、物品尺寸、画面面积和视觉醒目程度不能单独决定等级；单个低矮小物品处于转弯后的落脚区域时不能因数量少而降级，大量醒目物品也不能因容易看见而抵消通道占用。单张图片无法可靠判断的空间关系保留为 `unknown` 或 `insufficient`，不推断住户的视力、步态、认知状态或实际路线。

当前版本不使用 RTMDet-tiny 等传统目标检测模型，不需要下载 COCO 预训练权重、制作 CVAT 检测框、从零训练模型或导出 ONNX。仓库中的采图和标注工具用于离线评测、发现误判和回归验证，不参与住户日常使用。

## 当前产品流程

```text
萤石移动告警或本地画面变化
→ C6c 抓取当前图片
→ 后台确认通道参考画面是否可用
→ VLM 比较参考画面和当前画面
→ 输出画面质量、物品类型、位置、横纵向占用、通行影响、绊倒风险和风险框
→ 固定规则使用风险框与通道开口的重叠比例校正结论
→ APK 显示绿色、黄色或红色状态，并执行提醒与复查流程
```

首次启用时，后台会检查当前画面是否适合作为通道参考。通道可正常通过时自动保存；画面不合适时稍后重试。摄像头角度明显变化后，后台会重新识别。住户无需拍摄或标注参考图。

## 为什么仍然采集图片

当前图片数据用于以下工作：

- 建立固定测试集，比较提示词、模型版本和规则修改前后的效果；
- 统计明显挡路场景的漏检率；
- 统计通道边缘正常置物被错误要求整改的比例；
- 检查白天、开灯、夜视、背光和轻微视角变化下的稳定性；
- 核对风险框是否覆盖真正需要关注的物品；
- 保存能够复现问题的案例，避免修复一个场景后影响其他场景。

这些图片不会自动用于训练。以后只有在 VLM 成本、离线运行或响应时间无法满足要求时，才单独评估轻量 CV 模型，相关方案需要重新立项和准备独立数据集。

## 采集建议

先为每个固定摄像头建立 80–150 张有代表性的评测图片，无需收集数千张高度重复的连续帧。建议至少覆盖：

| 场景 | 需要包含的内容 |
|---|---|
| 畅通 | 没有临时障碍，保留靠墙或门边的正常物品 |
| 边缘安全 | 纸箱、鞋或袋子位于通道边缘，正常行走无需绕行或跨越 |
| 潜在风险 | 通道轻微变窄，但仍可直接通过 |
| 需要整改 | 物品伸入常用落脚区域，需要绕脚、侧身或跨越 |
| 严重风险 | 通道中央被明显占用或基本无法正常通过 |
| 无法判断 | 过暗、过曝、严重模糊、遮挡或主要通道不可见 |
| 视角变化 | 摄像头小幅偏移和明显转动后的画面 |

每个关键场景应包含不同距离、角度和光线。同一摆放连续抓到的近似图片只保留少量样本，避免评测结果被重复画面放大。

不要采集卫生间、换衣区等私密区域。画面出现人脸、门牌、纸面联系方式时先做脱敏，并在取得参与者同意后再用于测试。

## 使用 C6c 采集试验图片

先在 `.env` 中配置 C6c，然后在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\collect-c6c.py `
  --count 20 `
  --interval-seconds 30 `
  --camera-id c6c01 `
  --lighting day `
  --scene edge_safe_box
```

图片保存在 `evidence/c6c-collection/<camera-id>/`，文件名格式为：

```text
<camera-id>_<lighting>_<scene>_<时间戳>.jpg
```

同目录的 `metadata.csv` 记录文件名、采集时间、摄像头、光线、场景和文件大小。`scene` 是便于整理数据的名称，可使用 `baseline`、`clear`、`edge_safe_box`、`center_box` 等英文、数字、下划线或连字符。批量采集间隔不能低于 5 秒。

采集脚本只保存试验图片，不创建产品风险任务，也不改变后台自动维护的通道参考画面。

## 离线语义标注

运行本地标注页面：

```powershell
.\scripts\start-annotation.ps1
```

然后打开：

- 图片语义标注：<http://127.0.0.1:8010>
- 离线评测用通道区域：<http://127.0.0.1:8010/walkway>

标注内容包括画面质量、物品类型、物品所在区域、横向占用、纵向占用、通行影响、绊倒风险和可见依据。无需使用 CVAT，也无需逐个绘制目标检测框。完整字段见 [居家走道视觉标注规范](VLM_SAFETY_ANNOTATION_GUIDE.md)。

标注页面中的畅通参考图和通道多边形只服务于离线评测。产品运行时使用后台自动识别的参考画面和 VLM 返回的通道开口，不读取 `labels.json` 或 `walkway.json`。

## 独立评测 VLM

完成标注后运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\test-vlm-safety.py --model ecnu-plus --all
```

结果保存在：

```text
evidence/vlm-experiments/<时间>/results.json
```

脚本会输出总体字段一致率和各字段的一致数量。评测时不要只看整张图片是否所有字段完全相同，重点关注：

- 高风险漏检率；
- 边缘安全物品误整改率；
- `passage_effect` 与 `trip_risk` 的分项一致率；
- 红色与黄色风险框的定位有效率；
- 相同风险的通知和语音去重率；
- 从移动告警到 APK 显示结果的端到端延迟。

建议按摄像头、光线和场景分别统计，避免大量简单的畅通图片掩盖中央挡路、夜视或背光场景的问题。

## 旧接口说明

`POST /api/v1/ingest/vision-samples` 和 `POST /api/v1/ingest/safety-results` 为早期联调兼容接口。当前自动监测主流程直接使用 `/api/v1/devices/c6c/safety/*` 接口，不需要先上传训练图片，也不需要由外部目标检测程序回传 `clear/obstacle`。
