# 主动式多模态关怀MVP

本实现将已有VLM通道风险、睡眠助手个人基线和“小安”对话统一为主动关怀闭环。它用于发现值得询问的变化，不用于诊断疾病或预测真实跌倒。

Android首页以“小安”对话为首要入口，可直接查看最近对话、语音或文字输入，并处理画像确认和干预操作。主动关怀、居家安全、睡眠、联系人和设备状态作为可长按拖动排序的生活模块，顺序保存在本机。

## 大脑与设备工具

小安作为统一的“大脑”，负责理解自然语言、读取已经授权的数据、结合老人画像作出决策，再通过设备工具层调用摄像头、睡眠助手等“肢体”。设备本身不承担跨模块决策。每轮对话先由大模型根据语义和当前设备状态选择工具，而不是依赖设备名或固定关键词；例如“帮我看看家里现在怎么样”会调用摄像头抓图和VLM检查，再将真实检查结果交回大模型组织回复。

设备控制采用一次性授权：状态为`unset`时，首次设备调用显示“允许控制／暂不允许”按钮；选择允许后立即继续执行刚才的设备请求，并显示工具返回结果。选择后保存为`allowed`或`denied`，后续不重复询问。用户可在独立隐私页面随时修改或撤回。当前工具层支持摄像头在线状态、摄像头抓图＋VLM检查、读取或同步睡眠数据，以及通道检查、睡眠提醒和主动关怀的开启与暂停；后续设备通过同一网关注册。

## 事件来源

- `environment_risk`：C6c抓图经VLM和固定规则首次判断为中、高等级通道风险；
- `sleep_change`：至少7晚个人基线可用，且连续两晚存在显著变化；
- 日常对话：只提取本人明确说出的跌倒、近跌倒、跌倒担忧和活动回避事实。

## 画像确认

画像分为两条采集路径：

- 显性建档：老人从底部“画像”入口开始五步引导，依次选择居住情况、长期健康管理状态、提醒内容量、提醒呈现方式和家人联系规则。每道题只测量一个维度，选项互斥，并提供“其他／不确定／暂不填写”等必要出口。
- 保存与修改：每次选择或“暂不填写”都会立即保存为本人可见记录。未完成时再次进入会从第一项未填写内容继续；全部完成后再次进入先展示“这些内容已经保存”的汇总，只允许老人按字段修改，不重新从第一题开始。
- 隐性记忆：日常对话中的低敏感生活偏好、交流偏好和稳定习惯可以作为`inferred`记忆，不打断对话；跌倒经历、担忧、活动回避等风险信息仍必须显示确认按钮后才能进入正式画像。

`confirmed`和`inferred`内容都对老人本人可见，每条显示来源并支持删除。无感记忆不得包含疾病、用药、精确住址、财务、宗教、身份号码、联系人或家庭矛盾，并设置90天有效期。

日常对话提取结果首先保存为`candidate`。老人点击“记住”后变为`confirmed`，点击“不用记”后变为`rejected`。未确认事实不会进入下一轮LLM画像上下文。老人可以在“我的”页面查看和删除已确认事实。

健康情况采用两层记录。引导只记录“是否有经医生确认、需要长期管理的疾病”以及是否影响日常生活；具体病名只接受老人明确自报，并显示“记住／不用记”按钮。疾病和用药不得由LLM根据症状、睡眠、生理数据或语气推断。

## 环境风险沟通

发现通道障碍时，小安先说明位置、可见物和单步处理建议，再询问老人现在是否方便处理。默认选项是“我现在处理／稍后提醒／我现在不方便”，不因为普通纸箱直接建议联系家人。只有老人明确表示无法处理或主动提出帮助请求后，才提供联系家人的确认选项。

## 主动事件状态

`pending → engaged → completed`表示发现、开始沟通和本人已经回应。老人也可以选择`later`或`dismissed`。同一来源事件去重，普通事件遵守静默时段和每日上限，中高环境风险不受普通事件上限影响。

## 固定支持内容

资源定义在`app/care/interventions.py`。当前内容为比赛原型，LLM只能解释和推荐资源，不得自行生成治疗方案。真实老人测试前需由心理或临床专业人员审核。

非紧急睡眠或情绪场景先提供低负担自助支持，再在持续、加重或明显影响生活时建议进一步咨询。老人表达起夜后难以再次入睡时，系统提供30分钟白噪音按钮；只有本人点选后才从`app/care/white_noise`审核素材库随机选择并播放。Android端以独立音乐播放器显示素材名称，支持播放／暂停、上一首、下一首、停止、进度与音量调节；切换不重复当前素材。胸痛、呼吸困难、失去意识、正在跌倒等紧急情况仍优先进入固定紧急流程。
